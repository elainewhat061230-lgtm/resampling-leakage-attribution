# Decomposing the Performance Gains of Pre-Split Resampling in Imbalanced Credit Risk Modelling

Code, per-fold outputs and derived results for the preprint of the same title
(DOI: 10.5281/zenodo.23232311).

Resampling a class-imbalanced dataset before the train-test split is known to inflate reported
performance. This repository decomposes the gap between the correct protocol (resample after the
split) and the as-published protocol (resample before the split) into three path-specific
contributions, measured along four evaluation states on shared folds, so that the contributions
add up exactly to the total gap in every fold. The study covers six OpenML datasets, four models
(LogReg, DecisionTree, RandomForest, XGBoost), three resamplers (SMOTE, RandomOverSampler, ADASYN)
and 30 seeds (2,160 cells), plus a controlled imbalance ladder and an uncapped creditcard
robustness run.

## Headline results

- On ROC-AUC the prevalence contribution is zero and the synthetic-test mixture is the larger part
  under every decomposition order (60-73% of the total on the prespecified path).
- On F1 the prevalence contribution is 91% of the inflation under logistic regression but 38%
  under XGBoost.
- Protocol choice changed the best model in 53.5% of ROC-AUC comparisons, 6.3 times a seed-noise
  baseline of 8.6%.
- At the as-published endpoint XGBoost wins 80.2% of comparisons and logistic regression never wins.

All reported numbers are generated by the code in `Experiment/code/` and can be looked up in
`Experiment/RESULTS_GROUND_TRUTH.md`, `Experiment/figure_numbers.log` and `Experiment/tables/`.

## The four states and the decomposition

For every dataset, model, resampler and seed, one stratified 5-fold split of the original data is
shared by all four states. Preprocessing is fitted on the training fold O_tr only. The clean model
is trained on O_tr plus the synthetic rows of a resampler fitted on O_tr. A second resampler is
fitted on O_tr and the test fold O_te together; a random subset G_test of its synthetic rows,
sized so that O_te plus G_test is exactly 50/50, is set aside for the mixed test population, and
the leaky model is trained on O_tr plus the remaining synthetic rows. The clean and leaky training
sets have the same size and class counts in every fold.

| State | Model | Test rows | Test prevalence |
|---|---|---|---|
| CON | clean | original test rows O_te | natural |
| LON | leaky | original test rows O_te | natural |
| LMN | leaky (same fitted model as LON) | O_te plus synthetic rows G_test | class-uniform reweighting keeps the natural prevalence |
| LMB | leaky (same rows and predictions as LMN) | O_te plus synthetic rows G_test | unweighted, balanced 50/50 |

With M(state) the value of a metric in a state:

- L = M(LON) - M(CON): training-side leakage
- S = M(LMN) - M(LON): synthetic-test mixture
- P = M(LMB) - M(LMN): prevalence
- T = M(LMB) - M(CON) = L + S + P exactly

`states.py` checks the identity T = L + S + P in every fold (tolerance 1e-12) together with the
other invariants of the design, and stops a cell if any of them fails. Four supplementary factor
states (COB, LOB, CMN, CMB) are computed alongside and are used only for the decomposition-order
analysis.

## Requirements

Python 3.9 (the reported runs used Python 3.9.6 on macOS) and the package versions pinned in
`requirements.txt`:

```
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

- On macOS the XGBoost package needs the OpenMP runtime. If `import xgboost` fails with a
  `libomp` error, install it with `brew install libomp`.
- LaTeX is not needed. The included figures were rendered with Matplotlib's built-in text engine
  (Times New Roman and STIX fonts), which is also the default of `figstyle.py`. LaTeX rendering is
  used only when `FIGSTYLE_USETEX=1` is set (see the quick start).

## Quick start: rebuild every table, figure and the results file from the included per-fold outputs

```
cd Experiment/code
python3 rebuild_all.py
```

This runs `build_ground_truth.py`, `make_figures.py`, `rank_flip.py`, `make_tables.py` and
`rq5_explanations.py` in that order and overwrites `RESULTS_GROUND_TRUTH.md`,
`decomposed_cells.csv`, `figure_numbers.log`, `figures/` and `tables/` in `Experiment/`. The order
matters: `make_figures.py` clears `figure_numbers.log` and the later scripts append to it. It needs
no network access, because `rq5_explanations.py` reuses `Experiment/rq5_explanations.csv` when that
file exists. Measured runtime on the original machine: about 16 seconds (about 30 seconds with
`FIGSTYLE_USETEX=1`).

Figures are drawn with Matplotlib's own text rendering, which reproduces the included figures
whether or not LaTeX is installed. To render the figure text with LaTeX instead (needs `latex` and
`dvipng`), set `FIGSTYLE_USETEX=1`; this changes the typeface, not the numbers:

```
FIGSTYLE_USETEX=1 python3 rebuild_all.py
```

What to expect after a rebuild, as checked on the original machine from a clean copy of this
repository:

- `decomposed_cells.csv`, `figure_numbers.log` and every file in `tables/` are byte-identical to
  the included versions.
- `RESULTS_GROUND_TRUTH.md` differs only in its generation-timestamp line.
- The PNG files in `figures/` are byte-identical to the included ones (checked with and without
  LaTeX on the PATH) and each PDF differs only in its embedded creation date. On other systems,
  font availability can change the appearance of the figures, not the numbers in them.

Do not use `rebuild_all.py --check`: it calls an audit script that is not part of this repository.

To recompute RQ5 from the datasets instead of reusing the included detail, delete
`Experiment/rq5_explanations.csv` before the rebuild. The script then downloads the six datasets
and recomputes permutation importances; this took about 11 minutes on the original machine
(`rq5_run.log`).

## Run the tests

```
cd Experiment/code
python3 -m pytest -q test_states.py
```

Expected result: `20 passed`, in about 4 seconds on the original machine. pytest also reports
about 1,170 warnings: deprecation notices from imbalanced-learn 0.12.4 running on scikit-learn
1.6.1, and NumPy RuntimeWarnings raised inside scikit-learn's matrix products. One test
(`test_real_small_datasets`) loads pima and credit-g through `fetch_openml`, so it needs network
access unless those datasets are already in the scikit-learn cache (`~/scikit_learn_data`).

## Full re-run from OpenML

`run_main_grid.py` takes one optional positional argument, the mode. It has no other options.

| Command (from `Experiment/code/`) | What it runs | Jobs | Output | Runtime |
|---|---|---:|---|---:|
| `python3 run_main_grid.py` (same as `python3 run_main_grid.py main`) | main grid: 6 datasets x 4 models x 3 resamplers x 30 seeds, datasets capped at 20,000 rows | 2,160 | `raw/main__*.csv`, `raw_diag/main__*.csv` | 74.6 min |
| `python3 run_main_grid.py extreme` | uncapped creditcard (about 1:578), 4 models x SMOTE x seeds 0-4 | 20 | `raw/extreme__*.csv`, `raw_diag/extreme__*.csv` | 80.1 min |
| `python3 run_main_grid.py ladder` | controlled imbalance ladder: creditcard and bank-marketing, 400 minority rows, 6 ratios, 4 models x SMOTE x seeds 0-9 | 480 | `raw/ladder-r*__*.csv`, `raw_diag/ladder-r*__*.csv` | 50.9 min |
| `python3 run_main_grid.py pilot` | pilot of the four-state design (2 datasets x LogReg and RandomForest x SMOTE x 5 seeds, plus 5 cells with RandomOverSampler and ADASYN) | 25 | `pilot_4state/raw/`, `pilot_4state/raw_diag/` | 0.7 min |

Runtimes are for one machine with 8 worker processes and no GPU (`full_rerun_4state.log`; the pilot
time is from `run_main_grid.log`). Any other mode name stops with an error. In the ladder, the
1:255 rung of bank-marketing needs 102,000 majority rows, more than the dataset has, so its 40 jobs
are reported as insufficient and produce no files; 440 ladder cells are written.

How the driver behaves:

- It first checks the SHA-256 of `Ideation/preregistration_v2.md` against `config.py` and refuses
  to run if the file has changed.
- It runs cells in parallel with min(8, number of CPUs - 2) worker processes, at least 1; the
  models themselves are configured with `n_jobs=1`.
- It downloads each dataset with scikit-learn's `fetch_openml`, which caches it in
  `~/scikit_learn_data`.
- It can be resumed. A cell is skipped when both of its files exist and are complete (8 states x 5
  folds with no missing metric, and 5 diagnostic rows). Files are written to a temporary name and
  then renamed, so an interrupted run leaves no half-written file. Because the included `raw/` and
  `raw_diag/` are complete, running the driver on this repository as shipped skips every cell that
  has files (the 40 insufficient ladder jobs have none, so they are checked again and again
  reported as insufficient). To recompute a cell, delete its two files; to recompute a whole grid,
  move `raw/` and `raw_diag/` aside first. As a check, deleting `raw/main__credit-g__LogReg__SMOTE__seed00.csv` and
  `raw_diag/main__credit-g__LogReg__SMOTE__seed00.csv` and running `python3 run_main_grid.py`
  recomputed only that cell (2,159 cells skipped, about 4 seconds) and reproduced both files byte
  for byte on the original machine.
- A cell that fails, including any invariant violation, writes `<cell>.csv.error` with the traceback
  and produces no numbers; the driver then exits with status 2.
- Progress is appended to `Experiment/run_main_grid.log`.

After a re-run, rebuild the derived outputs with `python3 rebuild_all.py`.
`python3 pilot_report.py` recomputes the pilot invariants, and `python3 verify_independent.py`
compares an independent re-implementation of four cells with `raw/` (it also downloads datasets).
`RLA_DATA=pilot python3 build_ground_truth.py` builds a results file from the pilot data
(`pilot_4state/GT_PILOT.md`); it is meant for debugging only.

ladder runs start from the full datasets.

| File | SHA-256 |
|---|---|
| `Ideation/preregistration.md` (v1, frozen 2026-08-30T17:43:28) | `aa6bd88c029ad2afb58cfbb55ebe742f95bd8f30a5d08546fbb4f83d09e47006` |
| `Ideation/preregistration_v2.md` (v2, frozen 2026-08-30T20:36:41) | `c2790917d0a930a99773d0d20de491e54dc46d1b2df451a9c3326a8f2e412b87` |

v2 changes only the row-cap rule of v1. To check the hashes, run from the repository root:

```
shasum -a 256 Ideation/preregistration.md Ideation/preregistration_v2.md
```

(On Linux, `sha256sum` gives the same result.) The output must match the values above and
`Ideation/PREREG_FROZEN.txt`. `run_main_grid.py` performs the same check for v2 before every run.
In this public copy one personal identifier in the sign-off record of `PREREG_FROZEN.txt` is
redacted and marked as such; the hashes and timestamps it records are unchanged, and the two
preregistration files themselves are byte-identical to the frozen versions.

Deviations from the preregistration are recorded in `Experiment/DEVIATIONS.md` (in Chinese,
entries D-001 to D-011), including the replacement of the original five-arm design by the
four-state decomposition (D-011). The outputs of superseded designs are kept in
`Experiment/archive/`.
