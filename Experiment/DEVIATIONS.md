## D-001 · 截断规则错误 → 预注册 v2 + 全网格重跑

| 项 | 内容 |
|---|---|
| **发现时间** | 2026-08-30 19:00，v1 主网格跑完后建真源时 |
| **发现方式** | 真源第 0 节"数据完整性"表列出各数据集截断后正类比例，**adult 显示 0.5844**——与其自然比例 0.2393 严重不符 |
| **性质** | **规格错误，非代码错误。** 代码严格执行了 v1 预注册第 2 节的规则 |

### 错在哪

v1 规则："超过 20,000 行的数据集，保留全部少数类行，多数类随机下采样至总数 20,000"。

该规则在少数类**很小**时正确（creditcard 仅 492 个正例，不保全就没了）；在少数类**已经很大**时具破坏性：

| 数据集 | 自然比例 | v1 截断后 | 后果 |
|---|---:|---:|---|
| creditcard | 0.0017 (1:578) | 0.0246 (1:40) | 抬高 14 倍 |
| bank-marketing | 0.1170 (1:8) | 0.2645 (1:2.8) | 抬高 2.3 倍 |
| **adult** | 0.2393 (1:3) | **0.5844 (1.4:1)** | **少数类变成多数类** |
| credit-default | 0.2212 (1:4) | 0.3318 (1:2) | 抬高 1.5 倍 |
| credit-g / pima | — | 未超上限，未受影响 | ✓ |

**后果**：论文声称的 1:578→1:2 不平衡梯度不存在，六个数据集挤在近平衡区，adult 类别方向反转。直接打穿 RQ3，并削弱 RQ1 的外部效度。

### 为什么 v1 冻结前没抓到

冻结前**只核算了 creditcard 一个数据集**的截断影响（1:578 → 1:40），并把它写进限制节，然后想当然地推广到其余五个。而规则的破坏性随少数类占比上升而加剧——**creditcard 恰恰是受害最轻的那个**。

> **可迁移教训**：规格类改动必须在**全部单元**上验证，不得抽一个样本就推广。这与 RWP-002 的"单位 bug 存活两轮审计"同类——代码没错、执行没错，错在规格本身。

### 处置

1. **v1 原始数据全部保留**：`raw_v1_flawed_cap/`（2,160 个 CSV）、`RESULTS_GROUND_TRUTH_v1_flawed.md`、`decomposed_cells_v1_flawed.csv`。**不删除**，作为披露证据
2. **新建 `Ideation/preregistration_v2.md`**，SHA-256 `c2790917d0a930a99773d0d20de491e54dc46d1b2df451a9c3326a8f2e412b87`，**除截断规则外与 v1 逐字相同**
3. **v2 规则**：优先分层抽样保持原始比例；仅当分层后少数类少于 300 时，退回"保全少数类 + 补多数类至上限"
4. **冻结前在全部六个数据集上验证**（吸取本次教训）：

   | 数据集 | 自然比例 | v2 截断后 | 模式 |
   |---|---:|---:|---|
   | creditcard | 0.0017 | 0.0246 (1:40) | 保全少数类（分层仅剩 35 个） |
   | bank-marketing | 0.1170 | **0.1170 (1:8)** | 分层，比例保持 |
   | adult | 0.2393 | **0.2393 (1:3)** | 分层，比例保持 |
   | credit-default | 0.2212 | **0.2212 (1:4)** | 分层，比例保持 |
   | credit-g | 0.3000 | 0.3000 | 未截断 |
   | pima | 0.3490 | 0.3490 | 未截断 |

   修正后梯度：**1:40 · 1:8 · 1:4 · 1:3 · 1:2 · 1:2**
5. **全网格按 v2 重跑**

### 论文中的处理方式

**须在方法节或限制节明写**，不得隐去：本研究的截断规则在首轮预注册中设定有误，导致三个数据集的类别比例被抬高、其中 adult 的类别方向反转；错误在首轮结果生成时由数据完整性检查发现，随即修正规则、重新预注册并全量重跑。首轮数据保留可查。

## D-008 · 原始行识别判据：数据自带重复行时由哈希回退到保序，与预注册 §5 字面不符

| 项 | 内容 |
|---|---|
| **预注册原文** | §5："合成行识别以**逐行哈希**为准，顺序判据作交叉核验；两者不一致时记录在案" |
| **代码实际** | `arms.py:101` —— `is_orig = by_hash if not hash_degenerate else by_order`。即：数据含重复行时哈希退化（分不清原件与其复制品），改用 imblearn 文档化的保序行为 |
| **回退面（真源 §0 现算）** | 全网格 **1112 / 2160 格**走顺序判据；**仅 SMOTE 也有 292 / 720 格**——creditcard 120/120 · credit-default 116/120 · adult 56/120 · 其余三个数据集 0。原以为只有 ROS 会退化，实际这三个数据集**本身含重复记录** |

| **护栏** | 保序假设**逐折断言**并落盘 `order_ok`，真源核验 **57,600 / 57,600 通过**；`arms.py:97` 在"保序失效 **且** 哈希退化"时 `raise RuntimeError` 中止运行，不带着错误标签继续跑 |
| **数值影响** | 无重算需求：两条判据在非退化格上逐行一致（骨架验证 768/768、8000/8000），退化格上哈希本就不可用 |
| **论文位置** | §3.2 第二条实现约束（已按实际改写，含回退格数）；§4.11 第 8 条 post-hoc 清单已列入 |

## D-011 · 主设计重构：五臂（B/A/C/C₂/D/E）→ 四状态有序路径分解（CON → LON → LMN → LMB）

**日期**：2026-09-25　**性质**：分析设计的整体替换（数据、模型、重采样器、种子、截断规则、噪声带不变）

| 项 | 旧（五臂） | 新（四状态） |
|---|---|---|
| 折分 | B 在原始数据上分折；A/C/D 在**全量重采样后**的数据上另行分折（两套原始划分） | 每种子只在原始数据上分一次折，四个状态共享同一 O_tr / O_te |
| 预处理 | `get_dummies` + `fillna` + StandardScaler 在**全量数据**上拟合（D-003） | 每折只在 O_tr 上拟合（类别词表、缺失填充、标准化），再施加于 O_tr、O_te 与全量重采样输入 |
| 合成行识别 | 内容哈希 / 保序回退（D-008） | 重采样器输出前缀逐位断言 = 输入，合成行即其后缀（失败即中止） |
| 泄漏训练集 | 重采样后数据的训练折（大小与构成随划分而定） | O_tr + G_leak_train；与 CON 的 O_tr + G_clean **样本量、类别计数逐折相等** |
| 分解 | ③ = C − B，② = D − C₂，① = E − B，互不处于同一路径；A − B ≠ ①+②+③（缺口中位 F1 −0.0103） | L = LON − CON，S = LMN − LON，P = LMB − LMN；T = LMB − CON = L + S + P **逐折代数恒等**（容差 1e−12） |
| 汇总量 | 跨种子中位数 + 中位数的自助 CI | 跨种子**均值** + 均值的自助 CI（中位数不可加；中位数判据作稳健性对照，真源 §9） |

**ADASYN 的显式处理**：ADASYN 的生成数只近似目标（内部按密度比取整），干净侧与泄漏侧的合成训练行数可能不等。
规则：两侧取较小者 m，对多出的一侧做固定种子（`[seed, fold, 20260926]`）的均匀随机下采样；逐折记录修剪行数，
