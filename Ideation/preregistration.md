## 1. 研究问题（最终版）

| 编号 | 问题 | 性质 |
|---|---|---|
| **RQ1** | 划分前重采样造成的指标虚高，在①流行率变化 / ②合成测试行 / ③真泄漏三者间如何分配？各机制打在哪些指标上？ | **确认性 · 主贡献** |
| **RQ2′** | 协议选择是否改变"哪个模型最好"的结论？在什么条件下改变？ | **确认性 · 次贡献** |
| **RQ4** | 与已发表的划分前数字对照时，哪些指标可比、哪些不可比？ | **确认性 · 主贡献的落地面** |
| RQ2 | 纯泄漏项是否随模型容量变化？ | **确认性复现**（Roth 2026 已证，归功，不入摘要贡献） |
| RQ3 | 纯泄漏项是否随不平衡度变化？ | **确认性复现**（Demircioğlu 2024 已证，归功，不入摘要贡献） |
| RQ5 | 性能同档的模型之间 top-k 特征重要性是否一致？ | **探索性 · 下游小节**（须引 Rashomon / 分歧问题文献并说明区别） |

**方向性预测**（先写下，事后才能判断是否被推翻）：
1. ① 在 AUC / AUPRC 上恒为 0（**解析恒等，非经验预测**）
2. ① 在 F1 / accuracy / precision 上为正
3. ③ 随模型容量单调上升
4. 低容量模型上 ① 占主导；高容量模型上 ②③ 份额显著上升
5. RQ2′ 的翻转率**高于**同数据同模型的种子噪声基线
6. LogReg 的真泄漏项在主判据下**不确立**（骨架实测约 +0.004，CI 预计跨噪声带）——**这条预测若被推翻（即变成确立），说明种子数从 10 增到 30 后精度提升足够，属正常情形，如实报告即可**

## 2. 数据

**六个 OpenML 数据集**，`sklearn.datasets.fetch_openml(data_id=...)` 匿名拉取，人工步骤 0。

| 数据集 | OpenML id | 正类定义 |

| credit-g（German credit） | 31 | `bad` |
| Pima diabetes | 37 | `tested_positive` |

**预处理（固定，不调）**：
- 类别变量 `pd.get_dummies`；缺失填 0；特征转 float
- 特征标准化 `StandardScaler`，**在每个臂内部按该臂的训练集拟合**（避免引入本文正在研究的估计类泄漏）
- **截断规则**：超过 **20,000 行**的数据集，**保留全部少数类行**，多数类按 `default_rng(7)` 随机下采样至总数 20,000

> ⚠️ **须在论文限制节明写**：截断把 creditcard 的自然不平衡由 **1:578 改成约 1:40**。

**极端端的两重补偿**（因为截断削掉了本研究最有价值的一档不平衡）：

1. **受控阶梯**（第 5 节）：同一数据集固定少数类、只改多数类数量，覆盖到 1:256。单变量控制，因果比面板干净
2. **不截断稳健性检查**：creditcard **全量 284,807 行（1:578）**，4 模型 × SMOTE × **5 个种子**（种子 0–4），验证面板结论在真实极端不平衡下是否成立。实测成本：LogReg 3.7s · XGBoost 14.4s · DecisionTree 196s · RandomForest 约 538s（10 万行实测 189s 线性外推）→ **合计约 63 分钟**

> 若稳健性检查与面板结论冲突，**以稳健性检查为准并在正文明写**——截断是我们为算力做的让步，不是数据的性质。

## 5. 臂与机制（五臂，定义见 `Experiment/code/arms.py`）

| 臂 | 训练侧 | 评估对象 |
|---|---|---|
| **B 正确** | 划分后只对训练折重采样 | 原始测试折 |
| **A 照文献** | 划分前对全量重采样 | 全部测试行 |
| **C 真泄漏** | 同 A | 测试折里的原始行 |
| **D 合成难度** | 同 A | 原始多数类 + **与 C 等量**的合成少数类 |
| **E 纯流行率** | 同 B（干净模型） | 原始测试折，加权至 50/50 |

**③ = C − B　② = D − C　① = E − B**

**硬约束**（违反即结果无效）：
- D 臂的合成少数类**必须下采样到与 C 的原始少数类等量**，多数类取与 C 完全相同的那批
- 合成行识别以**逐行哈希**为准，顺序判据作交叉核验；两者不一致时记录在案
- 每臂每折的 `n_eval` 与 `prevalence` **必须写进原始 CSV**，供审计核对 C 与 D 是否真的等量等流行率

**受控阶梯（RQ3）**：creditcard，固定 400 个少数类样本，多数类下采样至 1:2 / 1:4 / 1:8 / 1:16 / 1:64 / 1:256。
**1:2 档是内建零对照**（数据已平衡，SMOTE 为空操作，③ 必须恰好为 0）。阶梯**须在 bank-marketing 上重跑一遍**以排除 creditcard 的天花板效应。

## 7. 重复与判据

- **种子**：30 个，取 `[0, 1, 2, …, 29]`。种子同时控制 CV 划分、重采样、模型随机性
- **交叉验证**：`StratifiedKFold(n_splits=5, shuffle=True, random_state=seed)`
- **汇报**：每个 (数据集, 模型, 重采样器) 单元格报 30 个种子的**中位数与全距**，不报均值±SD（分布右偏）

**判据（事前定死）**：

**主判据 —— 跨种子中位数的自助法 95% 置信区间**（百分位法，B=10,000，自助种子固定 20260830）：

| 判定 | 规则 |
|---|---|
| 效应**确立（正）** | CI 下界 **> +0.003** |
| 效应**确立（负）** | CI 上界 **< −0.003** |
| 效应**不确立** | CI 与噪声带 [−0.003, +0.003] 相交 → 报为"不确立"，**不解读方向与幅度** |
| 跨数据集**一致** | 6 个数据集中 ≥ 5 个各自确立且方向相同 |

噪声带取自 Roth (2026) §3.5 实测的种子噪声地板。实现见 `Experiment/code/decision.py`。

**辅判据 —— 30 次中同号次数，与主判据并列报告**，供直觉参照。两者结论不一致时，**分歧本身须报告**。

> **为什么主判据不用投票计数**（本节的设计理由，须在论文方法节交代）：
> 1. 投票只用符号、扔掉幅度。**实测证明它会被浮点级噪声骗过**——AUC 上的机制①是解析零（−1e-17 量级），投票判据却给出 10/10 一致的假象。已在 `decision.py` 里加幅度守卫，但这暴露了判据本身的性质
> 2. "30 次中 24 次"看着像"80% 多数"，实际严得多：**若真无效应，纯靠运气达到 24/30 的概率仅 0.07%**，比常规 p<0.05（约对应 20/30）严约 70 倍。这会把真实但幅度小的效应判成不确立
> 3. 二项尾概率实测：18/30 → 18.1% · 20/30 → 4.9% · 22/30 → 0.81% · 24/30 → 0.072% · 27/30 → 0.0004%
>
> **已知的边界情形**（预先声明，非事后发现）：骨架实测中 LogReg 的真泄漏约 +0.004 AUC，中位数高于地板但 CI 下界（约 +0.002）落在带内 → **主判据判不确立，辅判据 10/10 通过**。这一格必然出现分歧，论文须如实呈现，不得只报有利的那个。

**RQ2′ 的翻转率必须与三条基线并列报告**：
1. **本研究自测的种子噪声基线** ← 同一数据集同一协议下，换种子导致最佳模型改变的比例（**必须自测，不得只引 Roth 的 10.4%**，他的语料与模型集不同）
2. Roth (2026) 报的种子噪声 winner-flip 率 10.4%
3. Roth (2026) 报的指标选择 flip 率 31%
